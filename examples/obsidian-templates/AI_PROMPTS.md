# Готовые запросы для ИИ

Передавайте ИИ нужные образцы и [руководство](../../docs/OBSIDIAN_TEMPLATES.md) как файлы или текст. Одна ссылка на локальную заметку не означает, что ИИ может её прочитать. В примерах ниже замените текст в квадратных скобках. Для нового приключения сначала согласуйте план, затем генерируйте файлы.

## 1. Новая глава приключения

Скопируйте запрос и заполните вводные:

```text
Ты помогаешь мастеру готовить приключение для Obsidian и TaleBridge 0.7.0.
Используй приложенные руководство и образцы как контракт формата.

Кампания и тон: [например, мрачная тайна в портовом городе].
Группа и уровень: [состав, количество героев, уровень].
Итоги прошлой игры: [решения и последствия].
Установленные факты и важные NPC: [что нельзя менять].
Текущие цели героев: [список].
Существующие имена файлов: [список для ссылок].
Объём: [например, один план, три сцены, два NPC, один противник].
Длительность игры: [например, 3 часа].
Ограничения содержания: [темы, которых избегаем].

Сначала предложи короткий план и список новых файлов. Если не хватает
обязательных вводных, задай конкретные вопросы. Не выдавай догадки за канон.
После моего согласования подготовь полный Markdown для каждого нового файла.
У каждого результата укажи точный относительный путь, затем отдельный блок
Markdown из четырёх обратных кавычек. Не добавляй внешние кавычки в файл.

Требования:
- Одна сцена — один файл. Теги [сцены, сюжет], общая строка session,
  один заголовок #, точные поля цели, сенсорики и локации.
- Callout: один quote, один tip, один todo; persona и warning по необходимости.
  Каждая строка callout начинается с >. Типы строчные, без модификаторов + или -.
- На каждую сцену: цель, короткая зачитка без секретов, значимые детали,
  проверки с последствиями успеха и неудачи, минимум два пути продолжения
  и подсказка мастеру, если игра остановилась.
- NPC с тегом npc и playable: false; противники с тегом бестиарий.
  Для NPC, нужных в трекере, заполни hp, hp_max, ac, speed и таблицу характеристик.
- Характеристики только таблицей из шести колонок, атаки блоками dnd-action,
  одна строка на поле. Формулы с латинской d, например 1d6+2.
- Инвентарь: ## Инвентарь, формат из образца, вес одного предмета в кг.
- Короткие wikilink используй для существующих/создаваемых карточек NPC.
  Переходы на сцены указывай текстом или Markdown-ссылками.
- План сохраняй как 00_План сессии.md, без тегов сцен.
- Не создавай talebridge_id и служебные комментарии ID для новых сущностей.
  Не копируй активную концентрацию, журнал и потраченные ресурсы чужого героя.
- Не меняй существующие заметки, пока я не попрошу.
- Не обещай автоматическое создание боя, привязку камеры или показ материала
  только из текста заметки. Эти действия мастер выполняет в интерфейсе.

В конце: список связей между файлами, новые предположения для согласования,
проверка формата и короткий чек-лист того, что мастер должен проверить в игре.
```

## 2. Точечное обновление после игры

```text
Ниже приложены актуальные заметки Obsidian и итоги сессии.
Обнови только то, что следует из итогов. Формат TaleBridge сохраняй.

Итоги: [что произошло, кто выжил, какие решения приняты, какие награды выданы].
Нужно обновить: [точные файлы и разделы].
Не менять: [факты и разделы].

Сначала перечисли предлагаемые изменения по файлам. Для существующих заметок
дай небольшие фрагменты «было → стало» с точным заголовком раздела, чтобы я мог
внести их вручную. Новые сцены предоставь целиком отдельными файлами.

Сохраняй talebridge_id, ID сцен, ID предметов, границы журнала и текущее
содержимое talebridge, если изменение состояния не было явно запрошено.
Не обнуляй hp, ячейки, деньги, ресурсы или концентрацию стартовым шаблоном.
Не переписывай JSON-предметы и чужой журнал.
Не добавляй второй YAML или второй раздел Инвентарь/Заметки игрока.
Не переноси секреты мастера в журнал героя или публичную зачитку.
Если выводы противоречат заметкам, покажи конфликт и дождись уточнения.
Не исправляй неизвестные детали выдумкой.

Заверши сводкой канона для продолжения: важные факты, открытые линии,
отношения NPC, последствия и вопросы мастеру. Отдели её от импортируемых файлов.
```

## 3. Проверка совместимости перед импортом

```text
Проверь приложенные Markdown-файлы по руководству TaleBridge 0.7.0.
Это проверка формата и логических связей, не подтверждение запуска приложения.

Для каждого файла укажи: назначение, будет ли он распознан, ошибки,
минимальное исправление и оставшиеся вопросы.
Проверь YAML с первой строки, типы полей, теги и playable,
таблицу характеристик, dnd-action, ## Инвентарь и ## Заметки игрока,
вложенные игровые данные talebridge, callout сцен и поле session.
Проверь, что названия файлов сцен не попали под исключения,
у ссылок на NPC есть карточки, а секреты не включены в публичный текст.
Проверь отсутствие дублирующихся ID при копировании; существующие ID не меняй.
Не заменяй все файлы: выдай только нужные исправления.
Отдельно перечисли то, что надо проверить мастеру в TaleBridge и TaleSpire.
Не называй формат исправным, если обязательный фрагмент не был предоставлен.
```

ИИ помогает подготовить текст, но окончательные числа, баланс, канон и результат импорта проверяет мастер. Не передавайте ИИ коды входа, файлы настроек плагина и резервные копии всего vault без необходимости.
