# Obsidian и TaleBridge: памятка мастера, шаблоны и работа с ИИ

Практическое руководство для TaleBridge 0.7.0. Форматы сверены с парсерами приложения. Начните с короткого маршрута ниже; таблицы и расширенные поля нужны при более подробной подготовке.

## За пять минут: первая новая сцена

1. Откройте [набор образцов](../examples/obsidian-templates/README.md) и файл «Шаблон сцены».
2. Скопируйте содержимое блока Markdown в новую заметку `Сцены/Сессия 02 — Маяк/01_Сцена — Закрытые ворота.md`. Внешние четыре обратные кавычки не копируйте.
3. Оставьте `tags: [сцены, сюжет]`. Замените `session`, заголовок, цель, локацию, текст зачитки и развилки.
4. Заполните упоминаемых NPC отдельными карточками. Имя ссылки `[[Лина-Смотрительница]]` должно совпадать с именем файла карточки.
5. Откройте список сцен в TaleBridge и проверьте зачитку, улики и персонажей. Сохранение файла обрабатывается плагином; если открытый экран ещё показывает старые данные, запросите список заново или переподключитесь.
6. Для подготовки следующей части передайте ИИ [запрос на новую главу](../examples/obsidian-templates/AI_PROMPTS.md) вместе с нужными образцами и итогами прошлой игры.

## Что хранить в vault

Пример удобной структуры; имена папок обычно свободные. Приложение распознаёт персонажей по свойствам и тегам, а сцены — по тегам или имени файла, а не просто по папке.

```text
Кампания/
  00_Описание кампании.md
  Персонажи/
    Новый герой.md
    Лина-Смотрительница.md
  Бестиарий/
    Гоблин-Часовой.md
  Сцены/
    Сессия 02 — Маяк/
      00_План сессии.md
      01_Сцена — Закрытые ворота.md
      02_Сцена — Тропа к маяку.md
  Лор/
    Старый маяк.md
  Материалы/
    Порт.png
  Инструкции TaleBridge/
    README.md
    01_Шаблон игрового персонажа.md
    ...
```

Один персонаж — один файл. Одна сцена — один файл: это рекомендуемый способ для работы с ИИ. План сессии, локация, фракция, квест и описание кампании могут быть обычными Markdown-заметками. Они не становятся отдельными сущностями интерфейса только благодаря своему названию или ссылке.

У библиотеки образцов нет собственного YAML: готовые данные находятся внутри копируемого блока. Она не должна создавать фиктивных персонажей. Не превращайте образцы в активные карточки внутри `Templates`: сканер персонажей **не исключает эту папку**. Готовые шаблоны персонажей для встроенной команды «Вставить шаблон» храните вне игрового vault или используйте копирование из наших блоков. Дополнительный плагин шаблонизации не требуется.

## Персонажи: что заполнять

[Игровой персонаж](../examples/obsidian-templates/01_Шаблон%20игрового%20персонажа.md), [NPC](../examples/obsidian-templates/02_Шаблон%20NPC.md), [противник](../examples/obsidian-templates/03_Шаблон%20противника.md).

YAML находится **в самом начале файла**, между двумя строками `---`. Ключи полей оставляйте как в образце; значения могут быть на русском. Используйте пробелы для отступов. `true` и `false` пишутся без кавычек; числа — без единиц измерения и с точкой в дробях. Строку с двоеточием заключайте в кавычки.

| Поле | Как заполнять | Что делает приложение |
| --- | --- | --- |
| `tags` | `[персонаж, игрок]`, `[npc, союзник]` или `[бестиарий, враги]` | Определяет обнаружение и категорию карточки |
| `playable` | `true` для героя, `false` для NPC/монстра | Разрешает или исключает выбор персонажа игроком |
| `hp` | Текущие хиты, например `12` | Число от 0 до `hp_max` |
| `hp_max` | Максимальные хиты, например `12` | Максимум на листе и в бою |
| `ac` | Число, например `14` | Класс доспеха |
| `speed` | Строка, например `"9 м"` | Отображение скорости |
| `race`, `class` | Названия строками | Подписи на листе, не автоматический расчёт правил |
| `level` | Целое от 1 до 20 | Уровень отдельно от названия класса |
| `status` | Краткий текст | Описание статуса; не команда назначения боевого состояния |
| `talespire_name`, `talespire_id` | Обычно оставляйте приложению | Связь с TaleSpire; имя само по себе не гарантирует точную привязку |
| `talebridge_id` | Не создавайте и не меняйте вручную | Стабильный ID, который назначает TaleBridge |
| `talebridge` | Необязательный вложенный раздел | Игровое состояние, описано ниже |

Имя карточки берётся из **имени файла**, например `Новый герой.md`, а не из `name:` или заголовка `#`. Не используйте одинаковые имена NPC в разных папках, если хотите однозначные короткие ссылки.

Для героя оставьте `playable: true` и тег `игрок`. Для NPC укажите `playable: false`, `tags: [npc]`; добавьте `союзник` для союзников или `враг` для категории врагов. Для монстра используйте `бестиарий`: этот тег даёт категорию «Бестиарий». Поле `playable: false` не скрывает заметку от мастера.

После создания героя мастер выдаёт его персональный код в настройках TaleBridge. Код не нужно записывать в карточку, YAML или запрос ИИ. Подробности подключения — в [руководстве мастера](GM_GUIDE.md).

### Характеристики — именно таблица

```markdown
## Характеристики

| Сила | Ловкость | Телосложение | Интеллект | Мудрость | Харизма |
| --- | --- | --- | --- | --- | --- |
| 10 | 14 | 12 | 10 | 12 | 10 |
```

Сохраняйте шесть колонок, их порядок, строку разделителя и одну строку значений. Пишите значения характеристик, а не только модификаторы. Список вида `- **СИЛ:** 16` не заполняет таблицу характеристик приложения. Один персонаж должен иметь одну такую таблицу.

### Атаки и действия

````markdown
```dnd-action
name: Короткий меч
hit: +4
dmg: 1d6+2
type: Рукопашное оружие
desc: Колющий урон; дистанция 1.5 м.
```
````

Каждое действие оформляется отдельным блоком **`dnd-action`**, без отступа перед обратными кавычками. Это построчный формат: одна строка на поле. Кавычки вокруг значений здесь не нужны. `hit` — готовый бонус попадания, например `+4` или `-1`; `dmg` — готовая формула. Дистанцию, спасброски цели и особые условия описывайте в `desc` одной строкой.

Пишите латинскую `d`: `1d20+5`, `2d6+1d4+3`. Обозначения `2к6`, `2d6 огнём` и макросы VTT в поле формулы не используйте. Формулы и бонусы мастер задаёт сам; текст «универсальное» не переключает автоматически урон. Второй вариант удара создайте отдельным действием. Лечение и особенности, записанные как атака, не означают автоматического применения эффекта к цели.

### Инвентарь

```markdown
## Инвентарь

- [x] Короткий меч (кол-во: 1, вес: 1 кг) [Оружие] — Колющий урон 1d6+2
- [ ] Зелье лечения (кол-во: 2, вес: 0.2 кг) [Зелья] — Восстанавливает 2d4+2 хитов
```

- Заголовок — ровно `## Инвентарь`, без эмодзи; не `### Инвентарь`.
- Один предмет — одна строка. `[x]` означает экипирован, `[ ]` — лежит в рюкзаке.
- `кол-во` — целое от 1 до 100000. Вес — **одного** предмета, от 0 до 100000; для этих образцов используйте килограммы и десятичную точку.
- Категории для удобства: `Оружие`, `Броня`, `Зелья`, `Снаряжение`, `Квестовое`. Своя категория тоже допустима, но для стандартных фильтров проще придерживаться этих названий.
- Название и категория — до 500 символов без переноса строки и обратных кавычек; описание — до 4096. Максимум 1000 предметов.
- Простые новые предметы добавляйте в этом формате. Сложные названия с квадратными/круглыми скобками, тире-разделителями или многострочным описанием создавайте через редактор инвентаря приложения: он сохранит их без потерь.
- После сохранения приложение может добавить комментарий с ID или преобразовать строку в JSON с маркером. Это штатный формат. Существующие ID и JSON не переписывайте с помощью ИИ; редактируйте такие предметы через приложение.

Не используйте строку `Меч | Оружие | 1 шт | 1 кг`: это не поддерживаемая таблица полей. Категория `Зелья` сама по себе не означает лечение. Для лечебного зелья пишите явное описание `Восстанавливает 2d4+2 хитов`. Для других расходников эффекты проверяет мастер. Монеты заполняются в кошельке, а не суммой в строке инвентаря.

### Журнал игрока и секреты

Раздел `## Заметки игрока` предназначен для игрока и синхронизируется с его журналом. Используйте один такой раздел; первоначально пишите в нём обычный текст без вложенных заголовков. При сохранении приложение добавляет служебные границы, после чего внутри журнала могут появляться и заголовки.

Этот журнал, инвентарь и поля `talebridge` доступны владельцу героя. Секреты мастера храните в отдельной заметке лора или сцене. Наличие заголовка «Секреты» в доступном игроку поле не скрывает текст. При показе материала отправляется выбранный мастером текст — проверяйте его перед публикацией.

## Сцены: что попадает в пульт мастера

Возьмите [образец сцены](../examples/obsidian-templates/04_Шаблон%20сцены.md). Нужны YAML `tags: [сцены, сюжет]`, поле `session` и заголовок `# Сцена …`. Даже при таком имени оставляйте теги: так надёжнее переносить и переименовывать заметки.

| Разметка | Назначение | Как писать |
| --- | --- | --- |
| `session: "Сессия 02 — Маяк"` | Группа сцен | Одинаковая строка у всех сцен одной сессии |
| `# Сцена 1 — Закрытые ворота` | Заголовок сцены | Один заголовок первого уровня на файл |
| `**Главная цель сцены:** …` | Цель | Одной строкой |
| `**Сенсорика:** …` | Детали восприятия | Одной строкой |
| `**Локация:** …` | Место | В тексте сцены; поле YAML `location` его не заменяет |
| `> [!quote] Зачитать игрокам` | Зачитка | Один блок на сцену |
| `> [!persona] Имя NPC` | Отыгрыш | Можно несколько блоков |
| `> [!tip] Улики и проверки` | Подсказки | Один блок; каждый пункт на своей строке |
| `> [!todo] Развилки` | Переходы и подсказка мастеру | Один блок; отдельная строка `> - **Пинок мастера:** …` |
| `> [!warning] …`, `> [!danger] …`, `> [!caution] …` | Механика и опасности | Можно несколько блоков |
| `[[Лина-Смотрительница]]` | Упоминание персонажа | Короткая ссылка на существующую карточку |

Каждая строка тела callout начинается с `>`. Между блоками оставляйте пустую строку. Сохраняйте строчные типы `[!quote]`, `[!persona]`, `[!tip]`, `[!todo]`; не добавляйте к ним `+`/`-` для сворачивания. Обычный заголовок `### Зачитайте игрокам` не заменяет `[!quote]` и не заполнит отдельную карточку зачитки.

`КС 12`, варианты успеха и провала — инструкции мастеру; они не выполняют автоматическую проверку и не запускают бой. Укажите, что меняется при успехе, при неудаче и если герои пошли другим путём. Реплики удобно начинать с `—`: приложение умеет выделять такие строки.

Все wikilink в сцене парсер собирает как упоминания, в том числе ссылки на места. Чтобы список участников был понятным, NPC связывайте через `[[Имя]]`, а переходы между сценами указывайте обычным текстом либо Markdown-ссылкой. Если карточки NPC нет, ссылка сама её не создаёт.

### Один файл с несколькими сценами

Поддерживаются границы `## Сцена 1 — …`, `## 2 — …` или `## 🎬 …`. Внутри каждой сцены используйте `###` для обычных подразделов. Поле `session` общее для файла. Для новых приключений рекомендуются отдельные файлы: меньше риск случайно изменить границы сцены.

Не используйте в одиночной сцене внутренний заголовок `## Сцена …` как обычный раздел: он будет воспринят как новая сцена. Числовой `## 2 …` тоже может стать границей.

### Если сцена не появилась

Сканер пропускает заметки с именем, начинающимся на `00_` или `_архив`, содержащим `план` или `шаблон`; также исключены пути с `templates` и `tamplates` (без учёта регистра). Это относится к **сценам**, а не к персонажам. Поэтому план сессии называется `00_План сессии.md`, а игровые сцены — `01_Сцена …`, `02_Сцена …`.

Порядок списка зависит от пути и имени файла; используйте номера с ведущим нулём. `scene_id` во frontmatter не заменяет внутренний комментарий ID. Закладка камеры выбирается в интерфейсе TaleBridge: произвольное YAML-поле `bookmark` не привяжет камеру.

## Расширенное состояние героя

Проще заполнять заклинания, ячейки, навыки, ресурсы, временные хиты и кошелёк через лист TaleBridge. Приложение сохраняет их внутри **вложенного** свойства `talebridge`. Верхнеуровневый `spells:` или обычный раздел `## Заклинания` не заполняет список заклинаний.

Для первичной подготовки персонажа можно добавить следующий раздел **в уже существующий YAML между его границами `---`**. Не создавайте второй `talebridge:`: объедините поля с существующим блоком. Во время игры эти значения меняются; при обновлении биографии не заменяйте их стартовыми.

```yaml
talebridge:
  temp_hp: 0
  inspiration: false
  currency:
    cp: 0
    sp: 0
    ep: 0
    gp: 10
    pp: 0
  spellcastingAbility: int
  spellSlots:
    - level: 1
      current: 2
      max: 2
  spells:
    - id: spell_fire_beam
      name: "Огненный луч — пример авторского заклинания"
      level: 1
      dmg: "2d6"
      desc: "Урон увеличивается на 1d6 за каждый уровень ячейки выше первого."
      concentration: false
      prepared: true
  resources:
    - id: resource_luck
      name: "Удача — пример ресурса"
      current: 1
      max: 1
      resetOn: long
```

Это пример структуры, а не готовый официальный набор правил или заклинаний. Укажите свои значения. Для готового героя передавайте ИИ актуальное состояние, а не этот стартовый пример.

| Поле внутри `talebridge` | Формат |
| --- | --- |
| `currency` | Все пять целых неотрицательных значений: `cp` — медь, `sp` — серебро, `ep` — электрум, `gp` — золото, `pp` — платина |
| `spellcastingAbility` | `int`, `wis` или `cha` |
| `spellSlots` | Круг `level` от 1 до 9; `0 <= current <= max`; одна запись на круг |
| `spells` | Уникальные внутри списка `id`, название `name`, круг `level` от 0 до 9; `dmg` — только формула, `desc` — описание |
| `resources` | Уникальные `id`, `name`, `0 <= current <= max`, `resetOn`: `short`, `long` или `none` |
| `temp_hp`, `inspiration` | Неотрицательное целое и `true`/`false` |
| `savingThrowsProficient` | Список из `str`, `dex`, `con`, `int`, `wis`, `cha`; удобнее выбрать в интерфейсе |
| `skills` | Словарь навыков со значениями `none`, `proficient`, `expert`; заполняйте в интерфейсе, сохраняя используемые им ключи |

Для усиления заклинания ячейкой высокого круга нужен явный текст правила в `desc`, как в примере. Без него приложение не предполагает дополнительные кубы. Перед игрой проверьте предварительный просмотр формулы. Множественные цели и все особые эффекты заклинания мастер применяет отдельно.

`activeConcentration`, `concentrationChecks`, `deathSaves`, `hitDice` и прочее текущее состояние лучше менять через лист. ИИ не должен выдумывать проверки концентрации, менять ID активной концентрации или обнулять потраченные ресурсы. Автоматическое предложение спасброска концентрации зависит от зарегистрированного приложением урона; произвольное переписывание `hp` в Obsidian не равно команде нанесения урона.

## Добавление новой главы с помощью ИИ

1. Дайте ИИ краткую сводку кампании: тон, состав группы, текущие цели, последствия прошлой игры, важные NPC и список существующих имён файлов.
2. Приложите это руководство, нужные образцы и только те действующие заметки, которые действительно нужно изменить.
3. Укажите результат: например, один план, три сцены, две карточки NPC и один противник. Попросите отдельный путь и полный Markdown для каждого **нового** файла.
4. Для существующих заметок попросите точечный список изменений. Не заменяйте весь vault одним ответом ИИ. Не передавайте коды доступа и файлы настроек плагина.
5. Проверьте имена ссылок, игровые числа, формулы, секреты и последствия выбора. Новые неутверждённые факты ИИ должен перечислить отдельно.
6. Создайте новые файлы и внесите одобренные изменения в спокойный момент между сохранениями приложения. Проверьте карточки в TaleBridge до начала игры.
7. После игры обновите план сессии: что произошло, какие награды выданы и какие линии остались. По этой сводке ИИ готовит продолжение.

Готовые запросы: [новая глава, точечное обновление и проверка совместимости](../examples/obsidian-templates/AI_PROMPTS.md).

### Служебные данные: правило для мастера и ИИ

При **обновлении существующей сущности** сохраняйте `talebridge_id`, блок `talebridge`, комментарии `<!-- talebridge-scene:… -->`, `<!-- talebridge-item:… -->`, маркеры JSON и границы журнала `<!-- talebridge:player-notes:start -->` / `<!-- talebridge:player-notes:end -->`. Не переносите их на другую сущность.

При **создании нового персонажа или новой сцены копированием старой** удалите у новой копии ID исходного персонажа/сцены; не выдумывайте замену — её назначит TaleBridge. У нового героя не копируйте текущее состояние концентрации и чужой журнал. Для новых предметов используйте простые строки образца или редактор приложения. Внутренние ID уже существующих предметов не меняйте.

Автоматическое первичное назначение ID создаёт резервную копию, но это не замена резервному копированию всей кампании. Перед массовой правкой ИИ сохраните копию изменяемых заметок. Не редактируйте один инвентарь одновременно в приложении и через ИИ: сервер может отклонить устаревшую правку. При конфликте сначала сверьте изменения, затем повторите сохранение.

## Материалы, бой и камера

- Карты и изображения храните в `Материалы/` или другой удобной папке vault. В пульте мастера выберите материал и опубликуйте его; простая вставка `![[Порт.png]]` в лор не означает автоматический показ игрокам.
- Приложение поддерживает файлы PNG, JPEG/JPG, GIF, WebP, MP4, WebM, MP3, OGG, WAV; выдаваемый файл ограничен 25 МиБ. Перед игрой проверьте формат в браузере/TaleSpire.
- Текст письма или объявления держите отдельным публичным фрагментом и показывайте через интерфейс материалов. Не отправляйте туда заметку с секретами мастера целиком.
- Состав боя и инициативу задаёт мастер в трекере. Текст «два гоблина» в сцене не создаёт двух участников.
- Миниатюры и закладки камеры привязываются из TaleBridge в клиенте мастера TaleSpire. Ссылка `[[Гоблин-Часовой]]` в сцене не привязывает миниатюру.

## Проверка перед игрой

- [ ] У новых заметок YAML начинается с первой строки, корректен и содержит правильные типы значений.
- [ ] У героя есть `playable: true`, понятное имя файла и персональный код, выданный мастером.
- [ ] Характеристики видны на листе; это таблица из шести колонок.
- [ ] Атаки имеют ожидаемые бонусы и формулы; тестовый бросок проверен.
- [ ] Инвентарь показывает правильные названия, количество, категорию и вес.
- [ ] Кошелёк, ячейки и ресурсы находятся в `talebridge` либо заполнены через интерфейс.
- [ ] Сцены попали в нужную сессию; зачитка, улики, развилки и предупреждения заполнены.
- [ ] Упомянутые NPC существуют; в списке сцен нет планов и образцов.
- [ ] У новых сущностей нет скопированных ID; у прежних ID сохранены.
- [ ] Публикуемые тексты не содержат секретов мастера.

## Частые ошибки

| Симптом | Что проверить |
| --- | --- |
| Героя нет в выборе игрока | `playable: true`, тег `игрок`, корректный YAML; код привязан к этому герою |
| Карточка названа неправильно | Имя файла, а не заголовок `#` и не свойство `name` |
| Характеристики пустые | Таблица, порядок колонок, строка `---`, отсутствие замены таблицы списком |
| Предметы пропали или имя включает все поля | `## Инвентарь`; образец со скобками вместо разделителей `|` |
| В сцене пустая зачитка или улики | Callout `[!quote]` / `[!tip]`, знак `>` на каждой строке; берётся первый блок соответствующего типа |
| Сцена вообще не появилась | Теги, имя файла, исключения `00_`, `план`, `шаблон`, `templates`; новое получение списка |
| Локация не заполнена | Строка `**Локация:** …` в теле сцены |
| В участниках сцены лишние места | Все wikilink учитываются как упоминания; переходы оформите текстом/Markdown-ссылкой |
| Заклинания не появились | Вложенный `talebridge.spells`; верхнеуровневый `spells` и обычный список не читаются как заклинания |
| Сохранение отклонено | Новая версия заметки или неверный формат; сохраните черновик, сверьте данные, повторите |
| Сообщение о повреждённом предмете | Не заменяйте JSON обычным названием; восстановите запись из резервной копии или исправьте её перед продолжением |
