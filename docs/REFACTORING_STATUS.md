# Результат рефакторинга TaleBridge

5 ноября 2026. Ветка `codex/full-refactor`, целевая ветка PR — `main`.

## Реализовано

- Общий протокол v1: runtime-схемы, request ID, подтверждения, ошибки, ревизии, дедупликация и последовательное выполнение изменений между клиентами.
- Серверная авторизация: случайные индивидуальные коды, hash вместо открытого PIN, сессии на восемь часов, отзыв, ограничение попыток входа и проверка прав на каждый объект.
- Игрок получает только своего персонажа; GM-сцены и чужие журналы не рассылаются. Clipboard хоста и произвольная HTTP-выдача vault удалены.
- Сервер WebSocket переведен на `ws`: лимиты сообщений, соединений, очередей, heartbeat, backpressure и origin policy. UI раздается сервером на `/`, диагностика — `/health`.
- Плагин собирается из TypeScript-модулей. Разделены транспорт, сессии, обработчики, Markdown/YAML, репозиторий и индекс. Адаптеры клиента не импортируют store; тест проверяет отсутствие циклов.
- Запись заметок атомарна; конфликт ревизий отклоняется. Обновление атак сохраняет промежуточный текст, `$&` и `$1` остаются буквальным текстом, журнал поддерживает собственные заголовки и code fences.
- Персонажи, сцены, участники боя и предметы имеют устойчивую идентификацию. Ответ о другом персонаже не меняет выбранный лист; удаление/пересортировка не пропускают активного участника.
- Навыки, temporary HP, ресурсы, заклинания, вдохновение, saving throws и кошелек сохраняются в vault. HP листа и связанного участника боя согласуются сервером.
- Броски связываются с `rollId`, выданным TaleSpire, и исходным запросом. Составные выражения сохраняются целиком; неизвестный формат отклоняется. GM-команды Obsidian используют зарегистрированного исполнителя.
- Настройки host/port/scheme общие для HTTP, WebSocket и медиа. Идентификаторы работают и в LAN HTTP, где `crypto.randomUUID` отсутствует. Переподключение отделено от устаревших событий сокета.
- Журнал подтверждает запись только после ACK. Есть локальные черновики, ограниченная очередь, экспорт конфликта/восстановления и перенос выбранных полей старого кэша после сравнения с сервером.
- Перед миграцией ID создается исходная копия заметки. Служебные ID сцен и предметов записываются Markdown-комментариями. Публикации получают свежие ограниченные ссылки после перезапуска сервера.
- Общие и специализированные диалоги используют native dialog, имя, ограничение Tab-фокуса, Escape и восстановление фокуса. Добавлены связанные подписи основных полей и видимый focus indicator.
- 26 компонентов переведены на выборочные подписки Zustand. Убраны лишние импорты через общие barrel-файлы, GM/player страницы разделены на chunks.
- Windows-установщик сохраняет `data.json`, обновляет через staging, оставляет предыдущую поставку и поддерживает copy/Junction. Плагин всегда копируется, чтобы настройки не разделялись с каталогом исходников.
- Единый lockfile и Node 24 LTS; ESLint 10, TypeScript 6 и проверки обоих компонентов. CI для Windows/Linux, браузерная проверка, runtime release без `node_modules`. Actions закреплены SHA официальных v7.
- Версия компонентов 0.7.0, протокол 1. Лицензионные метаданные согласованы с существующим GPL v3 в корне.

Рефакторинг учитывает параллельно добавленные кошелек и расходники. При ожидании броска смена персонажа не применяет лечение к другому листу; уменьшение количества предмета использует актуальные данные.

## Что требует ручной приемки в целевом окружении

Эти проверки не подменялись заглушками и не заявляются выполненными:

1. Загрузка нового плагина в настоящем Obsidian, реальная совместная сессия TaleSpire с двумя игроками, камера и доставка результатов физических кубиков.
2. Поведение `quietResults` и фактическая видимость скрытых результатов в установленной версии TaleSpire. Контракт реализован по официальной API-документации, но симуляция не доказывает поведение игрового движка.
3. Установка HTTPS/WSS proxy, сертификатов и firewall в пользовательской инфраструктуре. Поддержка endpoint реализована; инфраструктура не изменялась.
4. Полная ручная приемка WCAG 2.2 AA: screen reader, весь набор экранов при увеличении, контраст каждого состояния и экранная клавиатура. Автоматическая проверка диалога не является сертификацией WCAG.
5. Профилирование чтения реального большого vault и TaleSpire WebView. Синтетический benchmark измеряет только in-memory индекс, без диска, YAML и игрового движка.

Реальные vault, настройки установленного Obsidian и запущенная игра во время рефакторинга не изменялись. Сборка подготовлена для ревью через PR; слияние и установка в рабочую кампанию не выполнялись.
