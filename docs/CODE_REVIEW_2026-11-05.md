Дата: 5 ноября 2026 года. Репозиторий: `F:\TaleBridge`.
Проверенная версия: `main`, коммит `9f3b05257abaf9b9c65d930f6ac92aa6aa012e5e`.

## Вывод

Проект представляет собой функционально насыщенный прототип интеграции Obsidian и TaleSpire с современной основой клиентского интерфейса. TypeScript и production-сборка проходят. Однако приложение **пока не готово к эксплуатации с недоверенными клиентами**: сервер не устанавливает личность и права подключившегося пользователя, раскрывает PIN Мастера, отдает приватные файлы хранилища и предоставляет доступ к буферу обмена компьютера хоста. Есть подтвержденные сценарии потери Markdown-текста и ошибочной синхронизации персонажей.

Наличие React 19, TypeScript 7, Vite 8 и Tailwind 4 само по себе не означает соответствия современным требованиям. Основной технический долг находится в протоколе обмена, контроле доступа, сохранности данных и проверках качества. Массовое обновление библиотек или переписывание интерфейса сейчас не являются первым приоритетом.

Рекомендуемая последовательность: закрыть доступ к приватным данным и опасным операциям → исключить потерю данных → согласовать протокол и синхронизацию → разделить инфраструктуру и предметную логику → улучшить доступность и выпуск сборок. Подробный план: [REFACTORING_PLAN.md](REFACTORING_PLAN.md).

## Объем и ограничения

- После уточнения пользователя выполнен `git pull --ff-only origin main`; рабочая ветка осталась `main`.
- Проверены структура всего проекта, манифесты, зависимости, конфигурация сборки, установщик и документация. Углубленно рассмотрены весь серверный файл плагина, WebSocket-мост, TaleSpire-драйвер, хранилища состояния, Markdown-запись, редактор заметок, инвентарь, бой, медиа, авторизация и общие компоненты интерфейса.
- Клиент содержит 136 файлов в `src`, около 12,1 тыс. непустых строк; серверный `main.js` — 1778 строк. Выполнены сквозные поиски потенциально опасных конструкций, сетевых команд, обработчиков и зависимостей между модулями.
- Продуктовый код не исправлялся. Добавлены отчет, план и воспроизводимые диагностические материалы.
- Реальные Obsidian/TaleSpire, игровая сессия, vault пользователя и его буфер обмена не использовались. Проверки обработчиков выполнялись в VM с заглушками; браузерная проверка использовала локальную сборку и подставной WebSocket.
- Это инженерное ревью с проверкой конкретных сценариев, а не сертификация безопасности или WCAG. Полный end-to-end тест официальных API TaleSpire, нагрузочный тест, аудирование всех платформ и независимый анализ каждого транзитивного пакета не выполнены.

## Что уже сделано хорошо

- React-компоненты разделены по страницам, виджетам, возможностям и сущностям; нет единственного огромного JSX-файла для всего приложения.
- Включены `strict` TypeScript, `noEmit`, современный target ES2022 и bundler resolution.
- Есть общий `ModalShell`, `ErrorBoundary`, хуки для Escape и подтверждения удаления, отдельные утилиты парсинга.
- Большая часть сетевых обращений сосредоточена в двух адаптерах: WebSocket и TaleSpire.
- Markdown выводится React-элементами; в проверенном `src` не найдены `dangerouslySetInnerHTML` и `eval`.
- Есть lockfile, примеры vault, инструкции GM/player и установщик для Windows.
- Плагин помечен `isDesktopOnly`, что соответствует использованию Node/Electron API.

## Найденные проблемы

Приоритеты: **P1** — исправить до передачи приложения недоверенным клиентам или использования для важных данных; **P2** — запланировать в ближайшие итерации стабилизации. P1 здесь не означает доказанную эксплуатацию через Интернет: необходима достижимость сервера; требования конкретного браузера могут дополнительно ограничивать запросы к локальной сети.

### R01 · P1 · PIN передается клиентам, серверной авторизации нет

Места: [main.js:1036](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/obsidian-plugin/main.js#L1036), [main.js:1179](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/obsidian-plugin/main.js#L1179), [GmAuthModal.tsx:15](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/symbiote/src/features/gm-auth/GmAuthModal.tsx#L15).

`HANDSHAKE_ACK` возвращает `gmPin` любому соединению. Сравнение PIN и отметка авторизации находятся в браузере; сервер не проверяет роль, токен сессии и принадлежность персонажа перед `UPDATE_*`, `SYNC_COMBAT_STATE`, `BROADCAST_HANDOUT`. Заглушечный клиент без учетных данных изменил HP чужого персонажа, включая отрицательное значение. Подключение обслуживается на `0.0.0.0`.

Исправить: серверная идентификация, сессии, проверка прав на каждую команду и объект, привязка игрока к character ID. PIN/секрет не рассылать и не сохранять как доказательство полномочий в клиентском storage. Проверки `S01`, `S02`.

### R02 · P1 · HTTP отдает произвольные файлы vault

Место: [main.js:1539](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/obsidian-plugin/main.js#L1539).

`/vault-file?path=...` сначала ищет файл по прямому пути в vault. Ограничения на `public/`, тип файла или список опубликованных материалов нет. Код отдает и `.md`, и другие `TFile`, а не только изображения. Проверка прочитала подставной `private/secret.md` без авторизации. Это раскрытие файлов внутри vault; выход за пределы vault этим ревью не доказан.

Исправить: явная область публикации и проверка права на каждый ресурс; канонизация пути; запрет выдачи остальных файлов. Проверка `S03`.

### R03 · P1 · Буфер обмена хоста доступен без авторизации

Место: [main.js:1489](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/obsidian-plugin/main.js#L1489).

HTTP `/clipboard` читает системный clipboard компьютера GM, `/clipboard-write` записывает его. Они доступны без сессии; CORS разрешен для любого origin. Следовательно, сетевой клиент может получать приватное содержимое или подменять вставляемый текст. Доступ из произвольного сайта также зависит от ограничений браузера на private-network запросы; прямой HTTP-клиент таких ограничений не имеет.

Исправить: отключить удаленный clipboard по умолчанию; по возможности пользоваться clipboard самого клиента. Если capability необходима — отдельное явное разрешение только доверенному клиенту хоста, аутентификация, allowlist origin и ограничение размера/частоты. Проверка `S04`; реальный clipboard не читался.

### R04 · P1 · Скрытые сцены и заметки доступны игрокам на уровне протокола

Места: [main.js:1113](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/obsidian-plugin/main.js#L1113), [main.js:1127](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/obsidian-plugin/main.js#L1127), [main.js:1133](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/obsidian-plugin/main.js#L1133), [main.js:1276](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/obsidian-plugin/main.js#L1276).

`SCENES_LIST` со всем содержимым сцены, включая `nudge`, механику и `raw`, рассылается всем клиентам. `GET_NOTE` принимает произвольный путь/имя; `GET_PLAYER_DATA` — имя любого персонажа; `PLAYER_NOTES_SYNC` передается через общий broadcast. Скрытие экранов GM в интерфейсе не обеспечивает заявленную приватность журнала и сюжетных материалов.

Исправить: отдельные DTO для GM, владельца и остальных игроков; адресная доставка приватных ответов; публикация только разрешенных частей сцены. Подтверждено трассировкой серверных обработчиков; отдельного живого многопользовательского теста не было.

### R05 · P1 · Обновление одного персонажа подменяет данные другого

Места: [main.js:1305](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/obsidian-plugin/main.js#L1305), [websocket.ts:225](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/symbiote/src/shared/api/websocket.ts#L225), [useRosterStore.ts:127](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/symbiote/src/shared/lib/useRosterStore.ts#L127).

Сервер broadcast-ит `PLAYER_DATA` после редактирования характеристик/параметров. Любой клиент принимает этот пакет в `playerData`, не сравнивая персонажа с `playerCharacterName`. Воспроизведено: выбран Alice, приходит Bob — выбор остается Alice, отображаемые данные становятся Bob. Следующая команда может отправить данные Bob от имени Alice.

Исправить: адресные ответы плюс проверка `characterId`/`requestId` на клиенте; хранить данные по ID, а не в одном безусловно заменяемом объекте. Проверка `F03`.

### R06 · P1 · Сохранение атак удаляет произвольный текст между блоками

Место: [main.js:375](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/obsidian-plugin/main.js#L375).

`updateCharacterActions` заменяет непрерывный диапазон от первого до последнего `dnd-action`, включая любые абзацы и разделы между ними. Проверка с двумя блоками и промежуточным `KEEP THIS TEXT` подтвердила удаление текста. Сейчас команда клиента дополнительно не совпадает с серверной (R10), но сам серверный обработчик доступен и дефект проявится после подключения этой команды.

Исправить: заменять только нужные узлы Markdown или управляемую секцию; гарантировать сохранение остального документа. Проверка `D01`.

### R07 · P1 · Неатомарная запись и интерпретация `$` повреждают заметки

Место: [main.js:347](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/obsidian-plugin/main.js#L347).

Последовательность `vault.read` → преобразование → `vault.modify` не сериализует параллельные изменения. Одновременное сохранение инвентаря и журнала воспроизвело потерю первого изменения. Кроме того, пользовательский текст вставляется строкой в `String.replace`; `$&` интерпретируется как исходное совпадение вместо буквального текста.

Исправить: атомарное `vault.process` либо совместимый с поддерживаемой версией Obsidian механизм записи, очередь изменений на файл и контроль ревизий; callback-функция в `replace`. Зафиксировать минимальную версию Obsidian после выбора API. Проверки `D02`, `D03`. [Официальное описание атомарного Vault.process](https://docs.obsidian.md/Reference/TypeScript+API/App/vault).

### R08 · P1 · «Сохранено» показывается даже при потере сетевой команды

Места: [websocket.ts:158](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/symbiote/src/shared/api/websocket.ts#L158), [PlayerNotesEditor.tsx:18](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/symbiote/src/features/save-notes/PlayerNotesEditor.tsx#L18).

`send()` молча отбрасывает команду, если WebSocket закрыт. Редактор журнала сразу устанавливает статус `saved`, не ожидая `PLAYER_NOTES_UPDATED`; повторной доставки нет. При возврате серверных данных локальная версия может быть заменена. Debounce-таймер редактора также не сбрасывается при смене персонажа/размонтировании и продолжает работать со старым замыканием.

Исправить: различать «локально», «отправляется», «подтверждено», «ошибка/конфликт»; подтверждать запись по request ID, сохранять черновик и управлять жизненным циклом debounce. Очередь команд вводить вместе с idempotency и revision, чтобы повтор не применял изменение дважды. Подтверждено по коду; отдельная проверка потери сети в браузере не выполнялась.

### R09 · P1 · Переустановка удаляет пользовательские настройки плагина

Место: [install.ps1:82](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/install.ps1#L82).

Если установленный плагин является обычной директорией, установщик после `rmdir` рекурсивно удаляет ее целиком. В этой директории Obsidian хранит `data.json`, а копия из исходников его не восстанавливает. При Junction пользовательские данные, наоборот, оказываются в каталоге исходников. Параметр `-CopyMode` объявлен, но нигде не используется. Отказ копирования и частичный результат не оформлены как надежная транзакция установки.

Исправить: сохранить `data.json`, проверить существующий тип цели и абсолютные пути, обновлять только файлы поставки через staging/backup, реализовать `CopyMode` и корректные exit codes. Установщик на настоящих каталогах не запускался; сценарий установлен статическим анализом.

### R10 · P2 · Атаки не сохраняются из-за разных имен команд

Места: [useRosterStore.ts:195](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/symbiote/src/shared/lib/useRosterStore.ts#L195), [main.js:1300](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/obsidian-plugin/main.js#L1300).

Клиент отправляет `UPDATE_CHARACTER_ATTACKS`, сервер обрабатывает только `UPDATE_CHARACTER_ACTIONS`. Изменение видно локально, но не записывается. Исправить общий контракт команд и добавить проверку клиент → сервер → перечитывание документа. Проверка `F02`.

### R11 · P2 · WebSocket-операции clipboard падают с ReferenceError

Место: [main.js:1415](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/obsidian-plugin/main.js#L1415).

Обработчик извлекает `type` и `payload` из `parsed`, но далее обращается к необъявленной `data`. Чтение и запись завершаются `ReferenceError`. Даже замена переменной требует учесть, что request ID находится внутри `payload`. Исправлять после закрытия сетевого доступа к clipboard по R03. Проверки `F01-*`.

### R12 · P2 · Команды браузерного fallback и некоторые команды хоста не доходят до исполнителя

Места: [talespire.ts:254](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/symbiote/src/shared/api/talespire.ts#L254), [main.js:1190](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/obsidian-plugin/main.js#L1190), [talespire.ts:134](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/symbiote/src/shared/api/talespire.ts#L134).

Клиент отправляет `ROLL_DICE`, `DICE_RESULT`, `GET_BOOKMARKS`, `GOTO_BOOKMARK` серверу, но соответствующих веток маршрутизации у него нет. `BOOKMARKS_LIST` сохраняется на сервере без доставки браузеру. Клиент также не подписан на входящий `ROLL_DICE`, который генерируют кнопки плагина Obsidian. Работоспособность прямого TaleSpire API не исправляет эти отсутствующие маршруты.

Исправить: явная регистрация исполнителя TaleSpire, маршрутизация команд/результатов и ограничения получателей, включая секретные броски. Проверка игнорирования сервером — `F07`; реальный TaleSpire API не тестировался.

### R13 · P2 · Медиа всегда запрашивается с компьютера игрока и порта 30123

Место: [media.ts:4](https://github.com/Anoonimik/TaleBridge/blob/9f3b052/symbiote/src/shared/lib/media.ts#L4).

`resolveMediaUrl` использует `127.0.0.1` и `DEFAULT_WS_PORT`, игнорируя настройки подключения к GM. На другом компьютере и при другом порте локальные картинки vault не загрузятся. Исправить единый объект endpoint для HTTP/WS и построение URL через него. Проверка `F04`.

### R14 · P2 · Часть данных персонажа теряется или остается только в одном браузере

### R15 · P1 · Собственный WebSocket-парсер нарушает RFC и не ограничивает ресурсы

## Оценка соответствия современным практикам

| Область | Оценка | Основание |
|---|---|---|
| Клиентский стек | Современная основа | React/TS/Vite/Tailwind, strict, корректная production-сборка |
| Типобезопасность | Частичная | Runtime-данные не валидируются, wire payload и TaleSpire API часто `any`, сервер JS не проверяется |
| Безопасность приложения | Существенные несоответствия | R01–R04, R15–R16; проверка полномочий и разделение данных отсутствуют |
| Протокол WebSocket | Выявлены нарушения RFC 6455 | Воспроизведены masking, fragmentation и Pong payload дефекты |
| Сохранность и согласованность | Недостаточна | R05–R08, R10, R14, отсутствие revision/ACK |
| Доступность | Есть конкретные барьеры; соответствие AA не подтверждено | R22, требуются клавиатура/screen reader/reflow/контраст |
| Тестирование и CI | Недостаточно | Нет регрессионного набора и автоматических проверок в исходном проекте |
| Производительность | Нужны измерения | Chunk 514 КБ, широкие store subscriptions, повторные полные сканирования vault |
| Поставка и сопровождение | Требует стабилизации | R09, R21, R24–R25 |

Для security backlog разумно использовать применимые требования стабильной [OWASP ASVS 5.0.0](https://asvs.owasp.org/downloads/): аутентификация, авторизация, валидация входа, защита данных и безопасная коммуникация. Формальную полноту ASVS этим отчетом не заявляем; уровень и применимость пунктов нужно согласовать с моделью угроз. Для воспроизводимой npm-установки следует использовать сохраненный корневой package-lock и [npm ci](https://docs.npmjs.com/cli/commands/npm-ci/), а не восстанавливать проект из `node_modules/.package-lock.json`.

## Дополнительные наблюдения

- Сканер перечитывает множество заметок при каждом подключении и изменении любого Markdown-файла. На соединении сервер сам отправляет roster/scenes, а клиент сразу запрашивает их повторно. Ввести индекс по metadata cache и инкрементальные обновления после профилирования.
- `scanCharacters` содержит специальные имена игроков, `scanScenes` — название конкретной сессии по умолчанию. Перенести кампанийные соглашения в конфигурацию/данные.

- HP листа персонажа и HP участника боя хранятся отдельно. Нужно явно определить источник истины и правила согласования; текущая система не обеспечивает единого транзакционного изменения этих представлений.

## Как воспроизвести

Диагностические проверки используют Node 24 API `stripTypeScriptTypes`; он выводит ExperimentalWarning. Скрипт не открывает настоящий vault, clipboard и сетевые соединения:

```powershell
node docs/audit/reproduce.cjs
```

Exit 0 означает, что описанные **дефекты воспроизвелись**, а не что приложение работает правильно. После исправления дефектов соответствующие проверки следует переписать на ожидаемое безопасное поведение.

Проверка зависимостей отправляет только имена и версии публичных пакетов в advisory API npm:

```powershell
node docs/audit/dependencies.cjs
```

Для браузерного smoke-теста нужна тестовая сборка в `review-build`, Chrome и Playwright. `PLAYWRIGHT_MODULE` можно задать для своего окружения; путь по умолчанию привязан к окружению этого аудита. Не входит в CI приложения:

```powershell
Set-Location symbiote
node node_modules/vite/bin/vite.js build --outDir ../review-build
Set-Location ..
$env:PLAYWRIGHT_MODULE = 'абсолютный путь к установленному playwright'
node docs/audit/browser-smoke.cjs
```

Временные папки исходников и сборки, созданные во время аудита, удалены; результаты проверок сохранены в `docs/audit`.
